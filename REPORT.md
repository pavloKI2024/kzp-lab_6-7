## 2. Мета роботи

Створити Python-застосунок, що читає CSV, перетворює текстові поля на типізовані значення, будує звіт за списками, словниками й множинами та записує його у файл. Досягнуто: пакет `kzp_lab06` із модулями loader, analysis, reporting, cli, тестами pytest і перевіркою ruff. Вхідний CSV — вивід ЛР5 (Java), приведений до англомовних назв стовпців.

## 3. Формат CSV

Заголовок: `room,guest,check_in,check_out,rate`.

| Поле | Тип | Правило |
|---|---|---|
| room | int | більше 0 |
| guest | str | не порожнє, пробіли по краях обрізаються |
| check_in | date | `YYYY-MM-DD` |
| check_out | date | `YYYY-MM-DD`, пізніше за check_in |
| rate | float | не менше 0 |

Екранований рядок: `102,"Коваль, Олена",2026-10-02,2026-10-09,2000.0` та `103,"Бондар ""Макс"" Максим",...`.

Правило порожнього входу: файл лише із заголовком дає порожній список і звіт з нулями; файл без заголовка або без обов'язкових стовпців — `DataError`.

Походження даних: `data/input.csv` отримано з `output/records.csv` ЛР5 (`заїзд,виїзд,гість,тариф,номер`) перейменуванням стовпців на `check_in,check_out,guest,rate,room` і впорядкуванням; значення не змінені.

## 4. Структура модулів

| Модуль | Призначення |
|---|---|
| `errors.py` | `DataError(ValueError)` |
| `loader.py` | читання CSV (`csv.DictReader`, UTF-8, `newline=""`), перетворення типів, номер рядка в помилках |
| `analysis.py` | відбір, словник, множина, `summarize`, `make_summary`; не працює з файлами |
| `reporting.py` | `format_report`, `write_report`; не читає CSV |
| `cli.py` | аргументи, коди завершення, межа помилок |

Імпорт модулів не виконує CLI-код: запуск лише під `if __name__ == "__main__":`.

## 5. Перетворення даних

- Список: `load_records` повертає `list[dict]`; `active_bookings` — list comprehension із умовою.
- Словник: `count_by_rate` — dict comprehension «тариф → кількість», ключі відсортовані.
- Множина: `unique_guests` — set comprehension.
- Типи: `room` → `int`, `check_in`/`check_out` → `date`, `rate` → `float`, `guest` → нормалізований `str`, додаткове поле `nights` (різниця дат).

## 6. Функції

`summarize(records, *metrics, minimum_nights=0, **labels)`: `minimum_nights` — типове значення, `*metrics` — назви числових полів, `**labels` — підписи метрик. Приклад: `summarize(records, "nights", "rate", minimum_nights=3, nights="Ночі")` → `{"count": 2, "Ночі": 10.0, "rate": 3200.5}`. Невідома метрика — `ValueError`; порожній відбір дає 0.0.

## 7. Алгоритм аналізу

1. Відбір активних на дату: `check_in <= reference_date < check_out`.
2. Агрегування: кількість за тарифом.
3. Унікальні гості; у звіті відсортовані.
4. Завантаження номерів: зайняті різні номери на дату з усіх відомих; найдовше проживання — перше за рівних, `None` для порожнього входу.
5. Порядок у звіті детермінований (сортування ключів і гостей).

## 8. Обробка помилок

| Ситуація | Реакція |
|---|---|
| хибне число, дата, порожній гість, порушені правила | `DataError("Рядок N: ...")` із `raise ... from error` |
| немає заголовка чи стовпців | `DataError` |
| немає файлу чи доступу | `OSError` → код 2 |

Приклад виводу помилки (stderr): `Помилка даних: Відсутні стовпці: check_in, check_out, rate` (код 1) і `Помилка файлу: [Errno 2] No such file or directory: 'data/missing.csv'` (код 2).

Номер рядка рахується від 2 (рядок 1 — заголовок). Голого `except` немає. CLI-коди: `0` успіх, `1` помилка даних, `2` помилка файлу; повідомлення йде в stderr в UTF-8.

## 15. Відповіді на контрольні питання

1. `pyproject.toml` описує пакет: назву, версію, мінімальний Python, залежності, команду запуску та налаштування інструментів.
2. Віртуальне середовище ізолює залежності проєкту від системного Python і відтворюється за `pyproject.toml`.
3. `newline=""` передає керування роздільниками рядків модулю `csv`, щоб він коректно читав переноси всередині лапок.
4. Словники, де і ключі, і значення — рядки.
5. `split(",")` розрізає й коми всередині лапок і не розрізняє переноси рядків у полях.
6. Список зберігає порядок і повтори, словник зіставляє ключ зі значенням, множина зберігає унікальні елементи без порядку.
7. Comprehension гарантує ясність для одного перетворення чи відбору; цикл краще, коли є кілька умов, побічні ефекти чи складне накопичення.
8. `*args` — кортеж позиційних аргументів, `**kwargs` — словник іменованих.
9. Змінний об'єкт за замовчуванням створюється один раз і зберігає стан між викликами.
10. `raise X from error` зберігає початковий виняток у `__cause__`, тож першопричина видна в traceback.
11. Так кожен модуль має одну відповідальність і його можна тестувати без файлової системи інших.
12. `with` гарантує закриття файлу навіть у разі помилки.
13. Інакше звіт залежить від порядку вхідних рядків, і його не можна надійно порівнювати й тестувати.
14. Файл лише із заголовком (порожній набір) і повністю порожній файл (помилка), відсутні стовпці.
15. Тест поведінки перевіряє результат для заданого входу, а не назви внутрішніх змінних чи кроків.
16. Файли `test_*.py` і `*_test.py`, у них функції `test_*`.
17. `ruff check` — стиль і типові помилки; `ruff format --check` — форматування без зміни файлів.
18. `0` — успіх, ненульовий (тут 1 і 2) — очікувана помилка даних чи файлу.
19. Тести перевіряють поведінку, аналізатор — якість коду, пакетування — що пакет справді встановлюється; жодне не замінює інше.
20. Вхідний CSV, його формат, перетворення, правила помилок, повний звіт, команди запуску та результати перевірок.
